# Hermes Ops

Личный дашборд: **проекты**, **мониторинг работы Hermes** (gateway, cron-джобы, запуски, активность) и
**ресурсы машин** (VPS + ПК). Статическое приложение на GitHub Pages, данные — в отдельном публичном
репозитории, но **зашифрованы** AES-256.

- Приложение: https://dwarf-alviss.github.io/hermes-ops/
- Данные: https://github.com/dwarf-alviss/hermes-ops-data

## Как устроено

```
VPS (cron, каждые 5 мин)                 GitHub                          Браузер
┌──────────────────────┐                ┌──────────────────────┐        ┌─────────────────────┐
│ collect.py --name vps│──┐             │ hermes-ops-data      │        │ login + пароль      │
│ (ресурсы + Hermes)   │  │             │  status.v1.json      │        │ = ключ расшифровки  │
└──────────────────────┘  ├─ publish.py →│  (шифртекст)         │←─fetch─│ AES-256-CBC         │
┌──────────────────────┐  │  + openssl  └──────────────────────┘        │ PBKDF2-SHA256 200k  │
│ ПК (cron, 5 мин)     │──┘  AES-256              ↑                   └─────────────────────┘
│ collect.py --push vps│                    GitHub Pages: hermes-ops (SPA)
└──────────────────────┘
```

1. **collection** — `collect.py` на каждом узле снимает метрики (`/proc`, `df`, `ps`, `docker ps`) и
   состояние Hermes (`gateway_state.json`, `cron/jobs.json`, `cron/executions.db`, `state.db`).
   ПК за NAT: снимок уходит на VPS по ssh (`--push vps`).
2. **publish** — `publish.py` на VPS собирает снимки, ведёт суточную историю, считает проблемы,
   шифрует payload через `openssl enc -aes-256-cbc -pbkdf2 -iter 200000` и пушит одним коммитом
   (`amend` + force push — история репы не растёт).
3. **frontend** — SPA (Vite + React + TS) на GitHub Pages: логин `kolya` + пароль = ключ расшифровки.
   Без пароля публичный репозиторий не читается.

## Разделы

- **Обзор** — статусы узлов, состояние платформ Hermes, сбои, активные проекты.
- **Машины** — CPU load, RAM, swap, диски, топ-процессы, контейнеры, суточные графики.
- **Hermes** — gateway (pid, агенты, платформы), расписания (статус, прогоны, сбои), последние запуски.
- **Проекты** — CRUD, приоритеты, дедлайны, ссылки; хранится в localStorage, есть экспорт JSON.
- **Настройки** — состояние данных, источники, экспорт расшифрованного снимка, выход.

## Безопасность

- В публичном репозитории лежит только шифртекст; пароль — единственный ключ.
- Логин не является секретом (он в бандле), защита — исключительно стойкость пароля к офлайн-перебору:
  PBKDF2 200 000 итераций. Пароль длинный и уникальный.
- Данные всё равно уходят в публичный репозиторий в зашифрованном виде — не кладите туда секреты
  (токены, пароли клиентов).
- Смена пароля: `bash collector/set-password.sh` на VPS — перешифрует следующую публикацию.

## Обслуживание

```bash
# VPS: состояние коллектора
crontab -l | grep hermes-ops
tail -20 /root/hermes-ops/publish.log
rm /root/hermes-ops/state/vps.json          # принудительный полный пересбор при необходимости

# ПК (WSL): снимок
systemctl --user status hermes-ops-collect.timer
```

Добавить новую машину: скопировать `collector/` на узел, запустить `collect.py --name <id> --push vps`,
добавить `<id>` в список узлов в `publish.py`.
